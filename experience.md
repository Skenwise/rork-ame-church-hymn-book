## 2026-10-17 — v1.0.9 build + Google Play 16 KB page-size rejection (fix)
- Play BLOCKED the first v1.0.9 upload: **"Your app does not support 16 KB memory page sizes"** (hard error; since Nov 2025 required for 64-bit libs).
- Root cause: `android/app/build.gradle` (Expo template) hardcodes `com.facebook.fresco:animated-gif:2.5.0` + `:webpsupport:2.5.0`. Those AARs ship `libgifimage.so` / `libstatic-webp.so` with ELF `PT_LOAD p_align=0x1000` (4 KB). RN core fresco 3.6.0's own libs ARE aligned — only the pinned 2.5.0 override was stale. (Also dragged animated-base/animated-drawable/fbcore/imagepipeline-base down to 2.5.0.)
- Fix: in app/build.gradle set `def frescoVersion = "3.6.0"`, use it for animated-gif/webpsupport/animated-webp, AND `configurations.all { resolutionStrategy.eachDependency { if (group=="com.facebook.fresco") useVersion("3.6.0") } }` to clear the 2.5.0 leftovers. Rebuild `bundleRelease` → arm64-v8a + x86_64 all 0x4000 ✅.
- Diagnosis tool (reusable): parse ELF program headers straight out of the AAB with python `zipfile`+`struct` (readelf cannot read a pipe). Requirement: every `PT_LOAD` `p_align >= 0x4000` (16 KB). Handle ELF32 vs ELF64 header offsets (`e_phoff`@0x1C/0x20, p_align@0x1C/0x30).
- NOTE: 32-bit ABIs (armeabi-v7a/x86) are ALL 4 KB-aligned — but Play only enforces 64-bit, so not blocking. AGP already 8.11.0 (the "bump AGP" advice did not apply); `useLegacyPackaging` does NOT change ELF p_align so it won't satisfy the check.
- ⚠️ `android/` is gitignored → this fix exists only in the local prebuild and is LOST on `expo prebuild`. A config plugin would make it durable.
- Outputs: ~/Downloads/AME-Church-Hymn-Book-v1.0.9.aab (Play upload) + -v1.0.9.apk (sideload), both signed (cert MD5 1531ff5e…), versionCode 8 / 1.0.9.

## 2026-11-05 — Offline premium fix + v1.0.14 (versionCode 14) APK/AAB
- **Bug**: a paid user went offline right after signing in, closed and reopened the app → treated as NOT premium ("Become a member"). Root cause: the Firestore `onSnapshot` was the ONLY source of premium status; offline it errors and the code forced `premiumUnlocked:false`. Firebase JS SDK has no offline persistence on RN (no IndexedDB), so there was no cache at all. Auth session itself WAS persisted (`getReactNativePersistence(AsyncStorage)`).
- **Fix v1** (`6fe43a0`): `lib/entitlement.ts` receipt cache (per-uid `entitlement.v1.<uid>`) + hydrate-from-cache in `onAuthStateChanged` + keep cached premium on snapshot error + clear on sign-out + "Offline — showing last confirmed status" in Settings + home banner no longer tells a signed-in user to sign in. **Client still reproduced the bug**: the receipt was written by a React effect after the first snapshot, so an immediate disconnect won the race and nothing was ever cached.
- **Fix v2** (`96a067b`, shipped): new `syncEntitlementNow(uid, status, fallback)` — forces `getDocFromServer(doc(db,"users",uid))`, writes the receipt with `AsyncStorage.multiSet`, retries 3× (800ms/1600ms backoff). `completeWebHandoff`, `signIn` and `signUp` all AWAIT it; a failed read throws `entitlement/sync-failed` → auth-callback shows a blocking "Couldn't confirm your membership" + Try Again instead of silently continuing as free. Receipt is now also written directly inside the snapshot callback (no effect delay) and a `fromCache` snapshot can never downgrade premium. `deviceStatus` mirrored in a ref (the listener is created once with `[]` deps, so state captured in the closure was stale). Added `entitlement.v1.lastUid` → if an offline cold start cannot restore the Firebase session, hydrate the last receipt instead of showing "not signed in"; explicit sign-out deletes the receipt FIRST, so a signed-out phone can never come back unlocked. Settings now shows "Last confirmed <time>".
- **Client confirmed the fix works** (offline relaunch keeps Premium). Release `eb7d314` bumped versionCode 13→14 (13 was never uploaded; Play live was 1.0.13/code12, so 14 is the next valid upload).
- **Build**: `cd android && ./gradlew assembleRelease bundleRelease` (APK 89MB, AAB 59MB). AAB manifest is protobuf-XML — `apkanalyzer` CANNOT read an AAB; parse `base/manifest/AndroidManifest.xml` with a tiny python protobuf wire parser (field 1 = XML text) to read versionCode/versionName. AAB signing check: `jarsigner -verify` + `unzip -p META-INF/*.RSA | openssl pkcs7 -print_certs | openssl x509 -md5` → same cert MD5 `1531ff5e…`.
- Outputs: ~/Downloads/AME-Hymn-Book-v1.0.14-code14.apk (sha256 909f0665…) + -code14.aab (sha256 e1f16036…). Both verified: versionCode 14 / 1.0.14, cert MD5 1531ff5e…, 64-bit ELF p_align ≥ 0x4000 (42 libs), new JS markers present.

## 2026-11-05 → 2026-11-10 — v1.0.14 live on Play + Play-ready prebuild plugin
- **v1.0.14 (versionCode 14) went live on Google Play** after the client confirmed the offline fix on a real device (sign in → force-stop → airplane mode → relaunch still shows ✦ Premium).
- `android/` is git-ignored, so BOTH release-critical native edits lived only in the local prebuild. Wrote `plugins/with-android-release-config.js` (registered in app.json) so `expo prebuild` re-applies them:
  1. **16 KB Fresco pin** — forces every `com.facebook.fresco` dependency to 3.6.0 (RN's aligned version) and keeps the `enable16KBPages` placeholder.
  2. **Release signing** — restores `signingConfigs.release` from env vars `HYMNBOOK_KEYSTORE_PATH` / `HYMNBOOK_KEYSTORE_PASSWORD` / `HYMNBOOK_KEY_ALIAS` / `HYMNBOOK_KEY_PASSWORD` (no secret in git). Without them the generated project signs release with the DEBUG key → Play rejects the upload ("upload key not recognised").
- **Key finding**: the ORIGINAL 16 KB problem came from an OLD Expo template that hardcoded `com.facebook.fresco:animated-gif:2.5.0`. The SDK 54 template no longer does — it uses `${expoLibs.versions.fresco.get()}`, and the `expoLibs` version catalog is built from **React Native's `gradle/libs.versions.toml`** (`fresco = "3.6.0"`). So a fresh prebuild is already aligned; the plugin is now insurance against template drift.
- **Config plugins only run when the native project is GENERATED**: `npx expo prebuild` over an existing `android/` folder does NOT re-apply them (proved: the gradle file kept the previous password). Use `npx expo prebuild --clean --platform android` when regenerating.
- **Plugin bug caught by diffing the generated gradle against the shipped one**: `String.replace(/defaultConfig \{/, \`$1...\`)` — the regex has NO capture group, so `$1` stayed literal and `defaultConfig {` was destroyed. Always use a function replacement when the replacement contains `$` sequences.
- **Verification recipe for a fresh prebuild** (scratch copy + `ln -s <project>/node_modules`): `./gradlew :app:signingReport` → Variant release / Config release / alias / cert MD5 (must be `1531ff5e…`); `./gradlew :app:dependencies --configuration releaseRuntimeClasspath` → every `com.facebook.fresco:*` must be 3.6.0; `diff` the generated `android/app/build.gradle` against the shipped one (the diff is what exposed the `$1` bug).
- Template differences worth knowing: SDK 54's release build type has `shrinkResources` OFF by default (`findProperty('android.enableShrinkResourcesInReleaseBuilds') ?: 'false'`) while the shipped 1.0.14 had it tied to `minifyEnabled`. Harmless (bigger APK, and safer for runtime-loaded fonts), but expect a size change next release.
- `versionCode`/`versionName` DO propagate from `app.json` through prebuild (14 / 1.0.14) — no manual edit needed there. The release signing config does NOT, hence the plugin.
